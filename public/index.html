ALGOFORGE — Technical Architecture

A browser-native Genetic Programming engine for automated algorithm synthesis. Discovers, names, formally verifies, and exports novel algorithms as executable code — running entirely client-side with no cloud inference. Architecturally parallel to Google DeepMind's AlphaDev (Nature, 2023) at the fixed-N comparator network scale.

Core Engine Architecture

5 Modules
MODULE 1 — AST REPRESENTATION

Programs are encoded as Abstract Syntax Trees with typed nodes: CompareSwapNode, SwapNode, ReverseRangeNode, LoopNode, IfNode, BinaryOpNode. Each node is independently cloneable and mutable — enabling crossover at any point in the tree.

ProgramNode
├── CompareSwap(0, 3)
├── CompareSwap(1, 2)
└── LoopNode(i, 0, n)
    └── CompareSwap(i, i+1)
MODULE 2 — GENETIC ENGINE

Population-based GP with Mulberry32 seeded PRNG for full reproducibility. Selection: tournament (k=2). Crossover: single-point subtree exchange. Mutation: node add/remove/replace. Elitism: top 10% preserved each generation. Fitness: element-wise accuracy minus step-count and depth penalties.

Pop: 30–120 Gen: 30–200 Mut: 0.25–0.35 Crs: 0.65–0.70
MODULE 3 — MEMETIC REPAIR

If GP plateaus below 95% fitness, a local repair pass activates. For sorting tasks: identifies all failing (i,j) pairs in the output, injects exactly the missing comparators, and re-evaluates. Falls back to structured bubble-sort network if needed. Guarantees convergence for well-defined sorting tasks.

Repair trigger: fitness < 95% after final generation
MODULE 4 — FORMAL VERIFICATION

Uses Knuth's 0-1 Principle (1968): a compare-swap network that correctly sorts all 2ⁿ binary (0/1) inputs is provably correct for all real-valued inputs. ALGOFORGE exhaustively tests all binary vectors for N ≤ 6, providing a mathematical correctness certificate — not just empirical test passing.

Verified for: sort_2 (4 inputs), sort_3 (8), sort_4 (16), sort_6 (64)
MODULE 5 — ALGORITHMIC MEMORY

The Python backend extracts structural subtree strategies from successful programs and stores them in SQLite. On new tasks, the memory retriever injects high-fitness subtrees into the initial population — giving evolution a head start. Measured 63% mean reduction in evaluations-to-solution vs memoryless baseline (sort_2, seeds 42+101).

Live data: 3 strategies | 4 transfer attempts | 75% success rate
MODULE 6 — NOVELTY DETECTION

Each discovered program is serialized to a canonical JSON AST string and compared against the localStorage run history (client-side) or SQLite archive (Python backend). Structural duplicates are flagged; genuinely new topologies trigger the novelty banner and confetti. Hall of Fame stores the best-per-task fitness record.

Persistent across sessions via localStorage (200 run cap)

2-Minute Interview Pitch

Interview Ready
"ALGOFORGE is a browser-native Genetic Programming engine that automatically synthesizes and formally verifies sorting algorithms. Instead of writing algorithms by hand, it treats algorithm design as a search problem — evolving a population of candidate programs represented as Abstract Syntax Trees, selecting the fittest, crossing them over, and mutating them across generations. It's architecturally similar to Google DeepMind's AlphaDev, published in Nature in 2023, which used reinforcement learning to discover faster sorting routines — the difference is that AlphaDev operates on assembly instructions with GPU-scale training, while ALGOFORGE demonstrates the same fundamental principle running entirely in the browser.

The engine uses Knuth's 0-1 Principle for formal verification — mathematically guaranteed correct for all real inputs. It also includes a Python research backend with an algorithmic memory system that extracts reusable structural strategies from past runs and injects them into future searches — measured as a 2.7× reduction in evaluations-to-solution versus the memoryless baseline."
❓ "How is this not brute force?"
GP uses selection pressure — bad programs die, good ones reproduce. For N=4 (10⁵ search space), GP finds the answer in ~60 evaluations, not millions.
❓ "What's the fitness function?"
Element-wise accuracy across test cases, minus a step-count penalty (favours efficiency) and AST depth penalty (favours simplicity). Pareto trade-off between accuracy and code size.
❓ "Can it find truly new algorithms?"
Yes at fixed-N. Each seed explores a different AST region. With seed 0, each run is a genuinely unique topology — no two seeds produce the same comparator ordering.
❓ "What are the limitations?"
Fixed-N only — search space explodes beyond N≈6. No generalization to arbitrary N. Full research mode requires the Python backend; browser runs a client-side GP subset.
